конфигурацию сборки. Правки этого прохода — удаление мёртвой HTTP-поверхности; поведение для клиента не меняется.

## 4. Находки по коду

**P1 — `x-session-id` это bearer-токен.** `SessionCtx` (`common/session.rs`) аутентифицирует только по UUID сессии
из заголовка; отдельного секрета клиента нет. Кто узнал UUID — действует как пользователь, пока сессия не истечёт.
Сейчас UUID живёт только в памяти десктопа и в логах не печатается, поэтому не горит, но: (а) нельзя логировать
этот заголовок, (б) при любом внешнем доступе к API сессию надо считать паролем. Рекомендация — привязать
сессию к отпечатку клиента или ввести короткий TTL + refresh на всех маршрутах.

**P2 — CORS отражает `Origin` и разрешает любые заголовки** (`router.rs:14-27`). `allow_credentials(false)`,
поэтому куки не утекут, а сессия передаётся явным заголовком — эксплуатировать нечем. Но «отражаем всё» мешает
заметить регресс: если когда-нибудь появится куки-аутентификация, эта конфигурация станет дырой.
Рекомендация — allowlist (`tauri://localhost`, `http://localhost:*`) вместо `mirror_request()`.

**P2 — `panic = "abort"` в release + 54 `unwrap()/expect()`.** Один паникующий разбор (больше всего в
`lyrics/genius.rs` — 11, `lyrics/util.rs` — 8) убивает весь процесс, а не один запрос. Либо `panic = "unwind"`
+ `CatchPanicLayer`, либо вычистить `unwrap` из парсеров лирики.

**P3 — сравнение админ-токена не constant-time** (`common/admin.rs`, `provided != expected`). По сети/loopback
практически неэксплуатируемо, но правится одной строкой (сравнение хешей или `subtle`).

**P3 — `AdminAuth` дублирует проверку пустого токена дважды** и возвращает одинаковый текст ошибки на
«токен не задан» и «токен неверный» — это правильно, но стоит закомментировать намеренно.

**P3 — дублирование курсорной пагинации.** `parse_cursor` + сборка `?limit=…&cursor=…` были в двух местах;
после удаления `local_likes::find_all` остался один экземпляр (`dislikes/service.rs`), но структура
(`has_more` → `next_href`) повторяется по модулям. Кандидат на общий хелпер.

**Хорошее, что не надо трогать:** `telemetry.rs` с `EnvFilter` (лог-уровни настраиваются, в отличие от
десктопа), `jemalloc`, `lto/strip/codegen-units=1` в release, `CompressionLayer`, 60-секундный
`TimeoutLayer` поверх всех маршрутов (длинные краулы обязаны быть фоновыми — сейчас так и есть).

## 5. Сквозная находка по логированию

Бэкенд логирует нормально (`tracing` + `EnvFilter`), а вот **десктопный `src-tauri` — нет**: `tracing` объявлен
в `Cargo.toml`, но `tracing_subscriber` никогда не инициализируется и нет ни одного `tracing::*` вызова —
58 `println!/eprintln!` идут прямо в stdout. В этом проходе самые горячие из них (`track_cache`: попадание в кэш,
коалесинг запроса, прогрев трека) закрыты `#[cfg(debug_assertions)]`, то есть в release больше не печатаются.
Остальные 55 — холодные (старт, ошибки, предупреждения) и остаются. Полный перевод на `tracing` требует
`OnceLock<AppHandle>` или `tracing-subscriber` — отдельная задача, её нельзя проверить без тулчейна.
